# R3 audit: SEC (permissions, guards, IDOR, money redaction, audit coverage)

Read-only audit. Every export in `src/server/mis` and every action under `src/app/(mis)` was scanned for a first-line `requirePermission`; all state-changing exports are gated except as noted. Ungated exports found are internal helpers (`getRuleValue`, `getAqlThresholds`, `lockStockKeys`, `notifyRoles`, etc.) or device-token doors, which are by design. Money redaction (`withoutRates`, `withoutMoneyFields`, `redactAuditForRole`) held up on every reader checked (BOM, PO, item, GRN, trace, audit page, print pages). The defects below are where the gate is missing or too weak.

## Verified OK (no finding)
- Every `src/server/mis` module's writing exports start with `requirePermission`. Gaps are only deliberate helpers, device-token doors and `dashboard.ts` (own-row, role-sanitised).
- `/api/mis/*` handlers: attendance/live, trace, docs, notifications, reports/wastage, employees/photo all delegate to gated functions; kiosk routes authenticate the device token before reading.
- `withoutRates`/`withoutMoneyFields`/`forRole` are applied in getBom, getPO, listItems/getItem/searchItems, GRN readers, trace, stock movement report; `/mis/print/po` refuses non-Owner; `audit/page.tsx` uses `auditChangesForRole`.
- Wage rule edits (`scheduleBusinessRule`, wage-type, payroll, pay-components, extra-pay approve) require `wages.read`; wage rule values are kept out of audit.
- Nav is generated from one table against the same `can()` matrix; no page found where nav shows a link the page refuses, apart from SEC-12.
